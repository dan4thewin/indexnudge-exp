## B2. Freshen deletes rows before re-index; parse failure = data loss
- **Needs:** **both** (code + tests)
- **Act or dismiss:** **Act** (high severity data loss)
- **Priority:** **fix-now**
- **Code change (Go):** in `doFreshen` (or the per-file freshen path):
  1. **Parse/extract first** into in-memory structs (`symbols, lines, calls, imports, defs, fts terms…`).
  2. If extraction fails for that file: **do not delete** existing rows; return/record an error for that file.
  3. If extraction succeeds: run a single transaction:
     - `BEGIN`
     - `DELETE FROM <each table> WHERE file_id = ?` (or path)
     - `INSERT` new rows
     - `COMMIT`
     - On any error: `ROLLBACK` (old rows remain).
- **Code change (Rust):** in `freshen` (or equivalent):
  - Same two-phase approach: extract first; only then transactional delete+insert; on parse failure **return an error** (or accumulate) and **do not delete**.

    - Setup: index file `a.go` containing `package p\nfunc Foo(){}\n`.
    - Assert baseline: `SELECT COUNT(*) FROM symbols WHERE name='Foo' AND file='a.go' == 1`.
    - Modify `a.go` to invalid Go: `package p\nfunc (\n`.
    - Run freshen.
    - Assert: **freshen returns error** (or reports file error), AND DB still has `Foo` symbol row and prior `lines` rows for `a.go`.
