## Blocking Issues

- **Wrong import line numbers**  
  **Impact:** `imports.line_num` is not a line number; `extractImports` stores `imp.Pos()` (`token.Pos` offset). Any line-based query is wrong.  
  **Fix:** Pass `fset` into `extractImports` and store `fset.Position(imp.Pos()).Line`.  
  **Test gap:** `TestImportsExtracted` only checks module names, so this bug passes.

- **`freshen` can delete good data on a failed reindex**  
  **Impact:** In `doFreshen`, existing rows are deleted **before** parsing/indexing the replacement. If parse/load/index fails, that file disappears from `lines/symbols/calls/imports/defs/files/channels`.  
  **Worse:** if all changed files fail, `reindexed == 0 && removed == 0`, so `directories` and `lines_fts` are **not rebuilt**, leaving derived tables stale/inconsistent.  
  **Fix:** Reindex in a transaction; only replace old rows after successful new indexing. Rebuild derived tables whenever any file was attempted/deleted, or make updates atomic.  
  **Missing test:** modify a file into invalid Go and run `doFreshen`.

- **Symbol identities are not globally unique across packages**  
  **Impact:** `qualified_name`, `caller_symbol`, `defs.symbol`, `lines.symbol` omit package path. In multi-package repos, `main`, `Add`, `Point.Distance`, etc. collide semantically and queries return ambiguous/wrong results.  
  **Fix:** Include package import path/package name in symbol keys and stored qualified names.  
  **Missing test:** two packages with same type/function names.

- **`loadPackages` ignores package/type errors**  
  **Impact:** `packages.Load` often returns `nil` error while `pkg.Errors` contains real load/type failures. You silently index partial/bad type info. This already shows up in tests: the sample source imports `sync` but never uses it.  
  **Fix:** inspect `pkg.Errors`; fail, warn, or explicitly degrade behavior.  
  **Missing test:** broken package with syntax/type errors and expected degraded behavior.

- **All DB writes ignore errors; indexing is non-atomic**  
  **Impact:** nearly every `Prepare`/`Exec` error is discarded. Constraint failures, DB locks, bad schema state, duplicate inserts, etc. can produce silent partial indexes.  
  **Fix:** check every DB error and wrap file/full-index operations in transactions.  
  **Test gap:** no test injects a DB failure or validates atomicity.

- **Fallback parse path loses channel range detection**  
  **Impact:** files not returned by `loadPackages` are parsed with `info=nil`; `extractChannels` then never records `range` over channels. Same file can index differently depending on package loading/build tags/errors.  
  **Fix:** type-check fallback files too, or explicitly document/flag reduced fidelity.  
  **Missing test:** standalone/build-tagged file with `for v := range ch`.

## Open-Ended Questions

### A. Most damaging issue not in findings list?

**The lack of any transactional or atomic semantics for the entire indexing operation.** If the process is interrupted mid-way through indexing (SIGKILL, power loss, OOM), the database is left in a partially indexed, inconsistent state with no way to detect or recover. For a tool meant to support "agentic querying," serving wrong/partial data silently is worse than failing loudly. A production-ready version needs either atomic DB swaps (build temp DB, then rename) or proper transaction wrapping with rollback.

### B. Largest missed opportunity?

**Cross-references and call graph resolution.** The tools extract calls but don't resolve them to definitions. Adding a `resolved_symbol_id` foreign key to `calls` that links `callee` → `symbols.id` would transform this from a text-search tool into a true code intelligence database. You could then answer queries like "what calls this function?" or "show me the full call graph" with simple SQL joins, which is the high-value use case for agentic code exploration.
