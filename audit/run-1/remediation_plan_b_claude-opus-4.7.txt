## fix-now

### B4 — Go line count off-by-one
- **Type:** code + test
- **Code:** In each Go extractor's line-population helper (the function that does `lines := strings.Split(src, "\n")`), replace with `bufio.Scanner` over `strings.NewReader(src)` using `ScanLines`, OR keep `Split` but trim a single trailing empty element only when the source ends with `\n`. Update both the per-line `lines` insert loop and the `files.lines` count (use `len(lines)` from the scanner, not from Split).
- **Test:** `TestExtractLinesTrailingNewline` — write a fixture `"package p\nfunc F() {}\n"` (3 logical lines) and assert `SELECT count(*) FROM lines WHERE file_id=?` == 3 and `SELECT lines FROM files WHERE id=?` == 3. Add a parallel case without trailing newline to confirm both produce the same count. Add a Rust counterpart `test_lines_trailing_newline` that already passes, locking in cross-language equality (`SELECT lines FROM files` must be identical for byte-identical `.go`/`.rs` fixtures with equivalent line structure).
- **Priority:** fix-now. **Action:** act.

### B3 — Go ignores DB write errors
- **Type:** code + test
- **Code:** Every Go extractor uses `stmt, _ := db.Prepare(...)` followed by `stmt.Exec(...)`. Change to:
  1. `stmt, err := db.Prepare(...)`; on err, return the error up to the indexer (don't continue with a nil stmt — current code panics).
  2. Capture `_, err := stmt.Exec(...)`; on err, wrap with file path + table name and return.
  3. Indexer top level: collect per-file errors into a slice; log them; bump exit code if any. Don't abort the whole index on one file.
- **Test:** `TestExtractorPropagatesPrepareError` — open DB, `db.Exec("DROP TABLE symbols")`, run extractor on a valid file, assert returned error mentions `"symbols"` and that no panic occurs. `TestExtractorPropagatesExecError` — open DB read-only (`?mode=ro`), call extractor, assert error returned. Currently these would panic / silently succeed.
- **Priority:** fix-now. **Action:** act.

### B2 — Freshen deletes rows before re-index; parse failure ⇒ data loss
- **Type:** code + test (both Rust and Go)
- **Code:** Reorder freshen to **parse-then-swap**:
  1. Parse file into in-memory staging structs (symbols, calls, imports, lines, defs).
  2. Begin transaction.
  3. `DELETE FROM <each table> WHERE file_id=?`.
  4. Insert staged rows.
  5. Commit. On any parse error in step 1, **skip** the file: log `"freshen: keeping stale data for X: parse error: ..."` and continue. Do **not** delete.
  - Rust: replace the current `delete_file_rows` → `index_file` sequence with `match parse_file(path) { Ok(parsed) => { tx.delete(); tx.insert(parsed); tx.commit() } Err(e) => warn!(...) }`. Critically, change current `Ok(())` swallow to bubble the warning into a counter on the freshen result.
  - Go: same restructure in `doFreshen`.
- **Test:** `TestFreshenPreservesDataOnParseError` (both langs):
  1. Index fixture with valid `foo.go` containing `func A()`.
  2. Assert `SELECT name FROM symbols WHERE file=?` == `["A"]`.
  3. Overwrite `foo.go` with `"package p\nfunc {{{"` (syntactically broken) and bump mtime.
  4. Run freshen.
  5. Assert symbol `A` still present, `files` row unchanged (or marked `parse_failed=1` if you add such a column), and freshen reports 1 skipped file.
- **Priority:** fix-now. **Action:** act.

### B6 — Rust `extract_span` byte/char index mismatch
- **Type:** code + test
- **Code:** In `extract_span` (the helper that slices `line[start_col..end_col]` using proc_macro2 `Span` columns): proc_macro2 columns are UTF-8 char counts, but `str` slicing is byte-indexed. Fix by walking the line: `let start_byte = line.char_indices().nth(start_col).map(|(b,_)| b).unwrap_or(line.len());` and similarly for `end_byte`, then slice `&line[start_byte..end_byte]`. Add bounds clamp so out-of-range columns return the trailing slice instead of panicking.
- **Test:** `test_extract_span_multibyte` — fixture `.rs` containing `fn café() { println!("é"); }`. Currently panics. Assert symbol name == `"café"` and that the span text in the `defs` table equals `"café"` byte-for-byte. Add `test_extract_span_emoji` with `let 🎉 = 1;` style identifier (or a string literal) to cover 4-byte UTF-8.
- **Priority:** fix-now. **Action:** act.

### C2 — Call callee naming → joinable to symbols
- **Type:** code + test
- **Code:** Add a `callee_qualified` column to `calls` populated by both extractors with a normalized form: `"<receiver_type_or_module>.<method>"` for Go and `"<path::to>::<fn>"` for Rust, leaving `callee` (raw text) intact. In Go's call extractor, when the callee is a `SelectorExpr` `p.Method`, look up `p`'s type from `types.Info.TypeOf(p.X)` and emit `pkg.Type.Method` (or `Type.Method` for local). For Rust, when the call is `obj.method(...)` and `obj` is in scope as `let obj: T = ...`, emit `T::method`; otherwise leave qualified blank.
  - Keep the join key language-agnostic: write a view `CREATE VIEW resolved_calls AS SELECT c.*, s.id AS callee_symbol_id FROM calls c LEFT JOIN symbols s ON s.qualified_name = c.callee_qualified`.
- **Test:** `TestCallJoinsToSymbol` (both langs): fixture defines `Point.Distance` / `Point::distance` and a call site. Assert `SELECT count(*) FROM resolved_calls WHERE callee_symbol_id IS NOT NULL` ≥ 1, and the resolved id matches `(SELECT id FROM symbols WHERE name='Distance' OR name='distance')`. This replaces tests that asserted bare-name equality (which encode the bug).
- **Priority:** strengthen. **Action:** act. Note: full method resolution in Rust without rustc type info is best-effort — accept that and document which call shapes resolve.

### T2 — Edge-case tests
